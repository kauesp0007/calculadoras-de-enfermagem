----------------------------------------------------------------------
  1. VISAO GERAL
----------------------------------------------------------------------
  O Blog de Enfermagem e gerado por um conversor proprio em Node.js.
  Voce NAO escreve HTML: escreve artigos em Markdown na pasta
  posts-markdown/ e roda um comando no terminal que gera tudo.

  Onde escrevo o artigo? .... posts-markdown/nome-do-post.md
  O que gera os HTMLs? ..... scripts/build-blog.js (npm run blog)
  Onde saem os HTMLs? ...... blog/ (NUNCA editar manualmente)
  Templates usados? ........ blog-templates/index.template.html
                             blog-templates/post.template.html
  URL do blog .............. https://www.calculadorasdeenfermagem.com.br/blog/
  URL de um artigo ......... https://www.calculadorasdeenfermagem.com.br/blog/<slug>.html

  REGRA DE OURO: blog/ e blog-templates/ sao pastas PROIBIDAS de alterar
  sem autorizacao. A fonte de verdade e posts-markdown/. Editar os HTMLs
  gerados e inutil: eles sao sobrescritos no proximo build.

----------------------------------------------------------------------
  2. ESTRUTURA FISICA
----------------------------------------------------------------------
  posts-markdown/ .......... FONTE DE VERDADE (onde voce escreve .md)
  blog-templates/ .......... templates (proibido editar sem autorizacao)
    index.template.html .... molde da pagina inicial ({{posts_list}})
    post.template.html ..... molde de cada artigo ({{title}}, {{content}}...)
  scripts/build-blog.js .... O GERADOR (executado por "npm run blog")
  blog/ .................... SAIDA GERADA (index.html + <slug>.html)
  img/ ..................... imagens do site (padrao .webp)
  package.json ............. script: "blog": "node scripts/build-blog.js"

----------------------------------------------------------------------
  4. CRIANDO UM ARTIGO DO ZERO (passo a passo)
----------------------------------------------------------------------
  1. Prepare a imagem de capa em /img/ (.webp, convencao de nomes - secao 7)
  2. Crie posts-markdown/nome-do-post.md
     (o nome vira a URL: blog/nome-do-post.html; minusculas, hifens, sem acento)
  3. Escreva o cabecalho (frontmatter) - secao 5
  4. Escreva o corpo em Markdown - secao 6
  5. Gere os HTMLs:  npm run blog
  6. Confira blog/nome-do-post.html e blog/index.html
  7. Rode o build obrigatorio do site:
       .\node_modules\.bin\tailwindcss -i ./src/input.css -o ./public/output.css --minify
       node gerar-sw.js
  8. Publique (commit/push e responsabilidade do desenvolvedor)

----------------------------------------------------------------------
  5. O CABECALHO (FRONTMATTER)
----------------------------------------------------------------------
  Todo artigo comeca com um bloco entre --- (obrigatorio):

  title: A Importancia da SAE e da NANDA na Pratica do Enfermeiro
  description: Entenda como a SAE e a NANDA contribuem para uma assistencia segura.
  date: 23 de Julho de 2026
  keywords: SAE, NANDA, enfermagem, diagnostico de enfermagem
  image: /img/livronanda-calculadoras-de-enfermagem.webp
  ---

  CAMPOS:
  title: ........ Titulo (card, H1 do hero, <title>, OG, Schema.org)
  description: .. Texto do card + meta description (curta, ~155 caracteres)
  date: ......... Data em portugues: "D de Mes de AAAA" (ordenacao da home)
  keywords: ..... Palavras-chave separadas por virgula
  image: ........ Thumb do card + og:image + twitter:image (regras na secao 7)

  COMO O image: VIRA URL (build-blog.js):
    /img/exemplo.webp .. -> https://www.calculadorasdeenfermagem.com.br/img/exemplo.webp
    img/exemplo.webp ... -> https://www.calculadorasdeenfermagem.com.br/img/exemplo.webp
    https://... (cheia) . -> mantida como esta

  PADROES (se campo faltar): "Sem Titulo", "Descricao indisponivel.",
  "Data nao informada", keywords "enfermagem", imagem iconpages.webp

  DATA - REGRAS:
  - Formato: "25 de Agosto de 2026" (dia + de + mes PT + de + ano)
  - Acentos nao importam (parser normaliza c->c, a->a, e->e etc.)
  - Ordena a home: mais novos primeiro; sem data valida -> fim

  6. SINTAXE MARKDOWN SUPORTADA (ordem exata do conversor)
----------------------------------------------------------------------

  9. O GERADOR (scripts/build-blog.js)
----------------------------------------------------------------------
  1. Config: caminhos + domain (https://www.calculadorasdeenfermagem.com.br)
     + baseUrl (.../blog/). Cria blog/ se nao existir.
  2. parsePost(): le frontmatter campo a campo, define slug
     (arquivo .md -> .html), monta canonical, guarda dateObj.
  3. parseDatePtBr(): "20 de Fevereiro de 2026" -> Date (acentos ok;
     fallback new Date()).
  4. Ordenacao: posts por data DESCENDENTE (mais novos primeiro).
  5. simpleMarkdownToHtml(): ordem = titulos -> imagens -> links ->
     listas -> negrito -> paragrafos -> agrupamento <ul>.
  6. Artigos: 7 replaces no post.template.html -> grava blog/<slug>.html.
  7. Home: acumula cards -> substitui {{posts_list}} -> blog/index.html.
  8. Logs: "Gerado: <slug>.html" e "Indice atualizado: blog/index.html".

----------------------------------------------------------------------
  12. TROUBLESHOOTING (erros comuns)
----------------------------------------------------------------------
  Thumb cinza no card ...... nome do image: nao bate com arquivo real
                             -> conferir sufixo e rodar npm run blog
  Barra invertida na URL ... img\arquivo no .md -> trocar \ por /
  Imagem existe, nao aparece  arquivo na raiz mas caminho diz /img/ (ou
                             contrario) -> raiz = /arquivo.webp;
                             pasta img = /img/arquivo.webp
  Post fora da home ........ .md fora de posts-markdown/ ou data invalida
  Ordem errada ............. date: fora do padrao "D de Mes de AAAA"
  Texto colado ............. falta linha em branco entre paragrafos
  Site ao vivo antigo ...... cache/sw antigo ou nao publicado
                             -> node gerar-sw.js + publicar
  Italico nao funciona ..... conversor nao suporta -> usar **negrito**
