1.1 VISÃO GERAL
---------------
O Sistema de Contas é um módulo de autenticação completo para o projeto
Calculadoras de Enfermagem, utilizando Firebase Authentication como backend.
A arquitetura segue padrão modular com Facade + Factory, permitindo que
qualquer página do site verifique autenticação com uma única linha de código.

Tecnologias:
  - Firebase Authentication (Web SDK v10.14.0)
  - JavaScript Vanilla (ES6+)
  - HTML5 + CSS3 (Tailwind CSS)
  - localStorage para cache de sessão
  - Firestore (estrutura planejada, Fase 2)

2.3 MÓDULOS JAVASCRIPT (js/auth/)
---------------------------------

2.3.1 js/auth/auth-core.js
    Camada: API Pública (FACADE)
    Padrão: Facade Pattern
    Dependências: firebase-init.js, auth-session.js, auth-providers.js,
                  auth-permissions.js, auth-user-profile.js

    Responsabilidade:
      - ÚNICO módulo que páginas HTML devem importar
      - Centraliza toda a lógica de autenticação
      - Delega para módulos especializados

    API exportada (window.Auth):
      INIT:
        Auth.init()                  Inicializa Firebase + listener de sessão
        Auth.isInitialized()         Verifica se sistema está pronto

      SESSÃO:
        Auth.isLoggedIn()            Usuário está autenticado?
        Auth.currentUser()           Objeto Firebase User ou null
        Auth.profile()               Perfil completo do Firestore
        Auth.signOut()               Encerra sessão

      LOGIN:
        Auth.signIn(provider, opts)  Inicia login ("google", "email", etc.)
        Auth.onAuthChange(callback)  Listener de mudanças de estado

      PLANO/PERMISSÕES:
        Auth.hasPlan(name)           Verifica plano ("free", "premium")
        Auth.hasPermission(name)     Verifica permissão granular

    Variáveis internas:
      _initialized   -> boolean  Sistema inicializado?
      _currentUser   -> object   Usuário Firebase atual
      _userProfile   -> object   Perfil do Firestore
      _currentPlan   -> string   Plano atual
      _listeners     -> array    Callbacks registrados


2.3.2 js/auth/auth-session.js
    Camada: Sessão
    Dependências: Nenhuma (usa apenas localStorage)

    Responsabilidade:
      - Cache local do perfil do usuário (localStorage)
      - Apenas dados NÃO SENSÍVEIS (sem tokens, senhas, pagamentos)
      - Detecção de expiração (30 dias)
      - Limpeza segura no logout

    API exportada (window.AuthModules.session):
      - persistProfile(data)     Salva perfil no cache
      - getCachedProfile()       Recupera perfil do cache
      - hasCachedSession()       Existe sessão em cache?
      - clearCache()             Remove todas as chaves auth_*
      - getLastLogin()           Timestamp do último login
      - syncWithFirebase(auth)   Sincroniza cache com Firebase Auth

    Chaves no localStorage:
      auth_profile     -> Perfil seguro (nome, foto, idioma, plano)
      auth_last_login  -> Timestamp do último acesso

    Tempo de expiração: 30 dias (SESSION_EXPIRY_DAYS)


2.3.3 js/auth/auth-providers.js
    Camada: Fábrica de Provedores (FACTORY)
    Dependências: Nenhuma

    Responsabilidade:
      - Registro central de provedores de autenticação
      - Cada provedor implementa a interface: { signIn(options), isAvailable() }
      - Isola os consumidores dos detalhes de cada provedor

    API exportada (window.AuthModules.providers):
      - register(name, module)   Registra um provedor
      - getProvider(name)        Obtém provedor (verifica isAvailable)
      - listProviders()          Lista todos registrados
      - hasProvider(name)        Verifica existência

    Provedores registrados:
      "google"     -> auth-google.js     (isAvailable: true)
      "email"      -> auth-email.js      (isAvailable: true)
      "microsoft"  -> auth-microsoft.js  (isAvailable: true, signIn: placeholder)
      "apple"      -> auth-apple.js      (isAvailable: true, signIn: placeholder)

    Interface de Provedor:
      {
        signIn: async function(options) => UserCredential,
        isAvailable: function() => boolean
      }

PARTE 4 - FLUXO COMPLETO DE AUTENTICAÇÃO
================================================================================

4.1 LOGIN COM GOOGLE
--------------------
1. Usuário acessa /conta/login.html
2. auth-ui.js inicializa -> _checkExistingSession()
3. auth-core.js -> FirebaseInit.init() -> carrega SDK Firebase do CDN
4. Firebase Auth verifica sessão existente (IndexedDB)
5. Usuário NÃO logado -> página de login exibida
6. Usuário clica "Continuar com Google"
7. auth-ui.js -> Auth.signIn("google")
8. auth-core.js -> providers.getProvider("google") -> auth-google.js
9. GoogleAuthProvider criado com prompt: "select_account"
10. signInWithPopup() -> popup Google abre
11. Usuário seleciona conta Google
12. Firebase retorna UserCredential { user }
13. auth-session.js -> persistProfile() no localStorage
14. onAuthStateChanged dispara -> _currentUser atualizado
15. Usuário redirecionado para home (/)


4.2 LOGIN COM EMAIL/SENHA
--------------------------
1. Usuário preenche email + senha
2. Clica "Entrar"
3. auth-ui.js valida campos (email regex, senha 6-128 chars)
4. Auth.signIn("email", { mode: "login", email, password })
5. auth-email.js -> signInWithEmailAndPassword()
6. Firebase valida credenciais
7. Sessão persistida automaticamente pelo Firebase Auth
8. Redirecionamento para home


4.3 CRIAR CONTA
---------------
1. Usuário clica "Criar conta"
2. Formulário exibe campo adicional "Nome completo"
3. Usuário preenche nome + email + senha
4. Clica "Criar Conta"
5. auth-email.js -> createUserWithEmailAndPassword()
6. updateProfile({ displayName })
7. auth-user-profile.js -> createProfile() no cache local
8. (Fase 2) Documento criado no Firestore
9. Usuário logado e redirecionado


4.4 RECUPERAR SENHA
--------------------
1. Usuário clica "Esqueceu a senha?"
2. Formulário mostra apenas campo de email
3. Usuário informa email cadastrado
4. auth-email.js -> sendPasswordResetEmail()
5. Firebase envia email com link de redefinição
6. Usuário clica no link -> define nova senha
7. Redirecionado de volta ao /conta/login.html


4.5 VERIFICAÇÃO DE SESSÃO
--------------------------
1. Usuário acessa qualquer página do site
2. global-scripts.js -> initializeAuthMenu()
3. Se scripts auth já carregados: reutiliza
4. Se não: carrega firebase-init.js -> auth-session.js -> auth-core.js
5. Auth.init() -> Firebase onAuthStateChanged
6. Se sessão existe no IndexedDB: usuário reconhecido automaticamente
7. Menu atualizado: mostra avatar + nome em vez de "Entrar"
8. Ao fechar e abrir o navegador: sessão restaurada automaticamente


4.6 LOGOUT
----------
1. Usuário clica "Sair" no dropdown do menu
2. Auth.signOut() -> firebase.auth().signOut()
3. Firebase limpa tokens do IndexedDB
4. onAuthStateChanged(null) dispara
5. auth-session.js -> clearCache() -> limpa localStorage
6. updateAuthUI(null) -> menu volta a mostrar "Entrar"
7. window.location.reload() para limpar estado da página

5.2 PADRÕES DE DESIGN
----------------------
Facade Pattern (auth-core.js):
  - window.Auth expõe API simples e unificada
  - Páginas HTML não conhecem Firebase, provedores ou cache
  - Trocar Firebase por Supabase = alterar apenas auth-core.js

Factory Pattern (auth-providers.js):
  - Provedores registrados dinamicamente
  - Novo provedor = novo arquivo + 1 chamada register()
  - Interface comum: { signIn(options), isAvailable() }

Singleton Pattern (firebase-init.js):
  - Firebase App inicializado uma única vez
  - Estado compartilhado entre todos os módulos

Observer Pattern (auth-core.js onAuthChange):
  - Múltiplos listeners notificados quando auth muda
  - Menu global, página de login, futuras páginas premium

7.2 PROBLEMAS CRÍTICOS (4 itens)
---------------------------------

C1. PLACEHOLDERS SEM PROTEÇÃO DE ROTA
    Severidade: ALTA
    Arquivos: perfil.html, configuracoes.html, historico.html,
              favoritos.html, assinatura.html
    Descrição: Nenhuma das 5 páginas verifica se o usuário está autenticado.
              Qualquer pessoa acessa /conta/perfil.html diretamente.
    Impacto: Usuário não autenticado vê placeholder sem contexto.
    Solução: Adicionar verificação Auth.init() + redirect para login.

C2. signInWithRedirect SEM getRedirectResult
    Severidade: ALTA
    Arquivo: auth-google.js
    Descrição: Quando o popup do Google é bloqueado, o código faz fallback
              para signInWithRedirect(). O usuário é redirecionado para o
              Google e depois volta, mas não há getRedirectResult() para
              capturar o resultado.
    Impacto: Login via redirect (popup bloqueado) falha silenciosamente.
    Solução: Adicionar auth.getRedirectResult() no auth-core.js init().

C3. IDs DUPLICADOS NO MENU MOBILE
    Severidade: MÉDIA
    Arquivo: menu-global.html
    Descrição: O ID "submenu-vagas-de-enfermagem" aparece 3 vezes no
              off-canvas menu, para seções diferentes.
    Impacto: Submenus mobile podem não abrir/fechar corretamente.
    Solução: Renomear para IDs únicos (submenu-vagas-emprego, etc.).

C4. RACE CONDITION NO MENU AUTH
    Severidade: MÉDIA
    Arquivo: global-scripts.js -> initializeAuthMenu()
    Descrição: updateAuthUI() roda via requestAnimationFrame após injeção
              do menu. Se os elementos ainda não existirem, retorna e
              nunca mais tenta.
    Impacto: Em conexões lentas, menu pode ficar sem atualização de auth.
    Solução: Adicionar retry com setTimeout ou MutationObserver.


7.3 NECESSITAM MELHORIA (8 itens)
----------------------------------

M1. auth-session.js: syncWithFirebase() exportada mas nunca chamada
    Ação: Remover ou integrar no auth-core.js init()

M2. auth-microsoft.js / auth-apple.js: Botões visíveis mas em erro
    Ação: Manter isAvailable=false até implementação real,
          ou esconder botões no HTML com display:none

M3. auth-user-profile.js: Firestore não implementado (Fase 1)
    Ação: OK para Fase 1. Implementar na Fase 2.

M4. auth-user-profile.js: createdAt como ISO string vs
    auth-permissions.js esperando Firebase Timestamp
    Ação: Padronizar para Timestamp na Fase 2.

M5. firebase-init.js: Versão 10.14.0 hardcoded
    Ação: Mover para constante VERSION no topo do arquivo.

M6. auth-ui.js: Manipulação de style.opacity inline
    Ação: Usar classes CSS .auth-loading para consistência.

M7. auth-email.js: Verificação de email comentada
    Ação: Habilitar sendEmailVerification() para produção.

M8. global-scripts.js: Logout força window.location.reload()
    Ação: Confiar no onAuthStateChanged para atualizar UI.
